# 第 13 章开发工作量计算

这里估算的是“在现有 `ha_framework` 上实现并验证旅行助手”的开发人时，**不是本次自动化执行的实际耗时，也不是旅行费用**。估算适用于一名熟悉 Python/Vue 的开发者；框架已存在、不重写框架，部署目标为本地可运行应用。

数据源：[workload.json](workload.json)。修改每项三点估计或风险预留后，在产品目录执行 `python estimate.py` 即可复算。

## 计算方法

```text
O = 乐观工时；M = 最可能工时；P = 悲观工时
单任务 PERT 期望 = (O + 4M + P) / 6
总期望 = Σ 单任务期望（先求和，最后舍入）
计划工作量 = 总期望 × (1 + 风险预留比例)
人日 = 计划工作量 / 每人日工时
```

默认风险预留 20%，每人日 8 小时。这里的预留是经验假设，不是统计置信区间。下表是工程判断，并非来自教材的官方工时。

**74 × 1.20 = 88.8 人时，约 11.1 人日。** 表内单项两位小数显示的舍入误差不应再次累计。该数字包含真实服务联调的计划量，不能据此宣称本机真实接口已经通过。

## 依赖与排期

```text
T01 → T02 → T05 → T06
         ↘ T03 → T04 → T11
T06 → T07 / T08 / T09
T04 + T07 + T08 + T09 → T10 → T12
T04 → T13（可选）
```

单人可按约 2–3 周工作日安排，具体取决于每天有效投入。多人不能直接把 11.1 除以人数当作交付周期：模型契约、服务联调、验收存在依赖；并行开发还会增加协调时间。本次实现没有派生开发子 Agent。

## 哪些成本没有重做

LLM 提供商适配、通用 Agent 推理循环、工具注册及 MCP 协议均直接复用。没有为了旅行业务重写记忆、RAG、评估、强化学习，也没有修改框架接口。复用收益体现在本估算的边界中，不再凭空给一个“节省百分比”。

## 主要不确定性

- 高德 POI 权限、可用结果及关键词适配；天气仅覆盖接口实际日期。
- 模型能否遵循工具格式与结构化输出；本版限制一次修复，避免无界尝试。
- 地图加载、浏览器安全配置及跨域图片；导出采用文字内容降低失败面。
- PDF 超长页面排版、移动端交互、保存与重算竞态。

未包含：账号系统、数据库、多用户任务隔离、后台任务队列、生产限流与监控、实时价格、路线优化、预订支付、地图商业配额与模型使用费。这些需要独立需求和估算，不能当作第 13 章本地工程的隐含零成本部分。

## 复算

```powershell
python estimate.py
python estimate.py --contingency 0.3
python estimate.py --input docs/workload.json --json
```

脚本会拒绝负值、无穷值、风险比例越界、每人日工时不合法，以及不满足 `O ≤ M ≤ P` 的数据。
